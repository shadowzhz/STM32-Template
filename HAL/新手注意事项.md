# STM32 HAL 新手注意事项

> 针对: STM32F103C8T6 · arm-none-eabi-gcc + Makefile · 无 CubeMX 手写工程 · 有 SPL 基础
> 模板: `STM32/HAL/Template`（下文说的 conf、main.c 都指模板里的文件）

---

## 一、新工程标准五步

1. 复制 `HAL/Template` 整个目录, 改名为你的工程名（连 `build/` 一起复制也行, 第一次 `make clean` 会重建）。
2. 在 `User/stm32f1xx_hal_conf.h` 里取消注释要用的外设模块, 例如用 SPI 就放开 `HAL_SPI_MODULE_ENABLED`。
3. 在 `User/main.c` 里写初始化: `HAL_Init()` → `SystemClock_Config()` → 各外设 `MX_xxx_Init()`。
4. 外设代码写成 `Hardware/xxx.c + xxx.h` 模块, Makefile 会自动搜索编译, **不需要改 Makefile**。
5. `make` 编译, `make flash` 烧录（ST-Link + SWD）。

## 二、工程规则

- **不要改 `Libraries/` 里的任何文件**。需要定制的部分（哪些模块启用、HSE 频率、时基优先级）全部在 `User/stm32f1xx_hal_conf.h`。
- `.h` 文件只放声明和宏, 函数体放 `.c`。头文件里写实现, 移植多个工程时会遇到重复定义。
- 头文件路径不用手动加: Makefile 用 `find` 自动搜索 `User Drivers Hardware` 下的所有目录。
- 换芯片时（如 F103C6/CB）要改三处: Makefile 的 `TARGET`/`FLASH_SIZE`/`RAM_SIZE`、Makefile 与 `.vscode` 里的 `STM32F103xB` 宏、链接脚本 `LENGTH`。启动文件 `startup_stm32f103xb.s` 与 64~128K 的 C8/CB 通用。

## 三、初始化铁律

**顺序不能乱**: `HAL_Init()` 必须最先调（它配置 SysTick 时基）, 之后 `SystemClock_Config()`, 之后才是各外设。

**时钟没开 = 静默失败**。STM32 上访问没开时钟的外设寄存器不报错、不 HardFault——读永远得 0, 写直接被忽略。症状是"配置明明写了却不生效"。每个外设初始化第一步必须是使能时钟:

```c
__HAL_RCC_GPIOC_CLK_ENABLE();   // GPIO
__HAL_RCC_USART1_CLK_ENABLE();  // 串口1
```

**检查每个 HAL 函数的返回值**。返回 `HAL_OK` 才算成功, `HAL_TIMEOUT` 意味着硬件没按预期响应（最常见: HSE 起振失败——晶振虚焊或板上根本没晶振）。统一进 `Error_Handler()` 死循环, 调试时在那里打断点, 一断一个准。

**F1 的 GPIO 速度只有三档**: `GPIO_SPEED_FREQ_LOW / MEDIUM / HIGH`（对应 2/10/50MHz）。没有 `VERY_HIGH`, 那是 F4 以后才有的。

## 四、F1 芯片专属的坑（其他系列没有）

- **AFIO 时钟**。任何引脚重映射、EXTI 端口选择都依赖 AFIO, 用到就先 `__HAL_RCC_AFIO_CLK_ENABLE()`（它挂在 APB2）。
- **重映射**。串口/定时器默认引脚不够用时, 用 `__HAL_AFIO_REMAP_xxx_ENABLE()` 搬到备用引脚, 如 `__HAL_AFIO_REMAP_USART1_ENABLE()` 把 USART1 从 PA9/PA10 搬到 PB6/PB7。
- **JTAG 占用引脚**。PB3、PB4、PA15 上电默认是 JTAG 功能, 想当普通 IO 用必须先:
  `__HAL_AFIO_REMAP_SWJ_NOJTAG();`（保留 SWD, 烧录不受影响; 不要用 `SWJ_DISABLE`, 会把 SWD 也关掉, 芯片直接"锁死"烧不进）。
- **总线归属**。使能时钟宏按总线分两族, 记不住就查芯片手册: APB2 上是 GPIO 全家、AFIO、USART1、ADC、TIM1; APB1 上是 USART2/3、TIM2~4、SPI2、I2C、PWR/BKP。开错总线的宏是编译错误, 算幸运。

## 五、中断与回调

中断处理是一条固定转发链, 你只写最后一环:

```
USART1_IRQHandler()            ← stm32f1xx_it.c 里加（引用中断号别忘了启动文件里已有向量）
  └→ HAL_UART_IRQHandler(&huart1)   ← 库函数, 判断事件、清标志
       └→ HAL_UART_RxCpltCallback(huart)  ← 你覆写的弱定义回调, 收满一字节/一帧进来
```

- **回调里不要延时、不要干重活**。置标志、搬数据、发信号量, 然后立刻返回。
- **`HAL_Delay()` 在中断里会死锁**。它靠 SysTick 中断递增 `uwTick`, 而本模板 `TICK_INT_PRIORITY = 15`（最低优先级）, 任何 ISR 里调 `HAL_Delay` 都等不到时基走动。中断里需要计时一律记时刻、主循环里判断（非阻塞）。
- **`HAL_UART_Receive_IT()` 是一次性的**: 收完指定长度就停。要连续接收必须在 `HAL_UART_RxCpltCallback` 里重新挂起。重复挂起会返回 `HAL_BUSY`——上一次还没收完又挂新的, 这也是新手最常见的"串口收了一次就不动了"的原因。
- **不定长接收直接用** `HAL_UARTEx_ReceiveToIdle_DMA()`（本驱动版本已有）, 配合 `HAL_UARTEx_RxEventCallback`, 空闲即成帧, 比"收满固定长度"的裸 Receive_IT 实用得多。
- **主循环和中断共享的变量必须加 `volatile`**, 否则开优化后主循环可能永远读不到中断里的修改（模板默认 -O0 看不出来, 一开 -O2 就炸）。
- 查某外设有哪些回调: 直接看 `Libraries/.../Inc/stm32f1xx_hal_xxx.h` 末尾, 回调都集中声明在那里。

## 六、DMA

- **缓冲区必须是全局或静态的**。DMA 在后台持续访问那块内存, 传局部变量地址, 函数返回后内存被复用, 收到的数据随机损坏。
- DMA 挂在中断完成收发, 同样遵守"回调里别干重活"。
- 排查 DMA 问题先看三样: 时钟开了吗、`HAL_DMA_Start`/外设 DMA 请求使能了吗、流控制器方向和宽度对吗。

## 七、时基与延时

- `HAL_Delay` 的精度是 SysTick 的 1ms, 且依赖中断能正常响应（见第五节）。
- 用 LL 的 `LL_mDelay` 时, 它按 `SystemCoreClock` 换算循环次数。时钟改过之后必须 `LL_SetSystemCoreClock(72000000);` 同步一下, 否则延时不准（`HAL_RCC_ClockConfig` 会自动更新这个变量, 手动改 RCC 寄存器不会）。
- 想要微秒级延时, 用一个基本定时器（TIM）计数, 或者 DWT->CYCCNT, 别用空循环——开优化后空循环会被优化掉。

## 八、错误处理与调试手段

按成本从低到高:

1. **返回值检查 + Error_Handler 断点**: 所有初始化函数的返回值都别放过。
2. **参数断言**: Makefile 里临时加 `-DUSE_FULL_ASSERT` 重编, 传错参数会进 `main.c` 里的 `assert_failed()`（已留壳）, 能定位到文件和行号。定位完记得去掉, 它有体积和速度开销。
3. **HardFault 定位**: 常见原因——空指针/野指针、栈溢出（链接脚本 `_Min_Stack_Size = 0x400` 是预留量, 大局部数组会真溢出）、回调函数指针被写坏。gdb 下 `bt` 看, 或查 `SCB->CFSR`。
4. **串口打印**: 把 `printf` 重定向到 UART（覆写 `_write` 或直接用 `HAL_UART_Transmit` 封装一个 `uprintf`）, 是性价比最高的运行时调试手段。注意用 `-u _printf_float` 才支持 %f（nano libc 默认裁掉了浮点打印）。
5. **gdb 单步**: `openocd` 起服务 + `arm-none-eabi-gdb` 连 `localhost:3333`, `load`/`b main`/`c`, 配合 VSCode 的 Cortex-Debug 插件更舒服。

## 九、编译/烧录问题速查

| 症状 | 原因 |
|---|---|
| `undefined reference to HAL_SPI_Init` | conf 里没开对应模块 |
| `undefined reference to Error_Handler` 之类 | 没包含对应头文件 / 函数没定义就调用 |
| 代码莫名改了没生效、全局变量值诡异 | 开了优化 + 缺 `volatile`；先用 -O0 调通再上 -O2 |
| Flash 超过 64K 报 overflow | 精简 conf 里启用的模块；检查是否误用 %f 等大函数 |
| 编译过、灯不闪 | 时钟开了吗 → 返回值查了吗 → BOOT0 跳线在 0 吗 → 晶振焊对了吗 |
| openocd 找不到目标 | SWD 四根线（SWDIO/SWCLK/GND/3.3V）接好；某些板要按住 RESET 上电 |
| 芯片烧不进、`protected` 字样 | 读保护开了, 用 openocd 解锁或 STM32CubeProg 全片擦除 |

## 十、代码习惯建议

- 外设句柄（`huart1`、`hspi1`…）定义在对应模块的 `.c` 里, `extern` 到 `.h` 供中断文件用; 不要全堆在 main.c。
- 中断服务函数统一写进 `User/stm32f1xx_it.c`, 它只做一件事: 调 `HAL_XXX_IRQHandler(&句柄)`。业务逻辑全部放回调。
- 每个功能一个 `Hardware/xxx.c/h`, 和 SPL 工程的组织方式保持一致, 移植经验可以直接平移。
- 遇到"这函数干嘛的/什么前置条件", 第一反应是跳进头文件看注释, 第二反应才是搜网页——HAL 头文件的注释比大多数博客准确。
